# Instructions for Overgear

This directory is the Overgear sublibrary, showcase and store. Read the root `AGENTS.md`, the shared `CONSTITUTION.md`, then `overgear/CONSTITUTION.md` before changing an Overgear interface.

- All new rules specific to this store belong in `overgear/constitution/rules.js`, including navigation, catalog, checkout, empty states, merchandising and brand choices. This also applies when the request arrives at the repository root
- Use a new stable `OG`-prefixed id; do not reuse or renumber existing ids. Keep `do`, `dont`, `why`, `source`, `check` and `signals`; name a local tool when a rule is checked by a script
- Keep product-specific checks and tests under `overgear/tools/` and `overgear/tests/`. General accessibility, tokens and reusable component behavior belong to baseui; do not copy its rules here
- Do not put a store rule in `src/constitution/rules.js`, shared `AGENT_DEFAULTS`, shared component usage guidance or shared audit tools. Dependencies go from Overgear to baseui, never the other way around
- Follow the shared violation protocol, using `ConstitutionBanner` from `overgear/index.jsx` in repository sources (or `baseui-kit/overgear` in a consuming app). It understands shared ids and the local OG ids
- Edit rule sources, then run `npm run constitution` and `npm run registry`. `overgear/CONSTITUTION.md`, `overgear/AGENTS.md` and `overgear/CLAUDE.md` are generated by `overgear/tools/build/constitution.mjs`; change this generator to update these authoring instructions
- Run `npm run test:overgear` for the rule boundary and product checks; run the regular suite for shared component changes
